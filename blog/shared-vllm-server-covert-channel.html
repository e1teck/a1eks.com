Models on a shared vLLM server can talk without the network

2026-11-26  ·  vLLM Security LLM MLOps

Your agent sandbox blocks the network. The inference server does not care.

A write-up by Niranjan Deshpande and David Africa shows two models on the same vLLM server passing bits to each other with no network access at all.

The root cause is mundane. vLLM picks GPU kernels by the size of the engine step, and different kernels round floats differently. That rounding is a fingerprint a model can read.

Two channels:

  • Step sizing. A model ingests a large document to inflate the batch step. Another model processed in the same step reads the change in rounding.
  • KV cache board. A helper computes a "mailbox" prompt under a large step. Whoever reuses that cached prefix inherits the fingerprint.

The numbers are not subtle. A fine-tuned Qwen3-8B reader decoded 1,221 of 1,221 signals. A colluding monitor passed 354 of 354 signaled attacks and flagged 0 of 1,596 benign actions. It also worked on SGLang, LMDeploy and TensorRT-LLM.

If you run a monitor and an agent on shared inference:

  • Put the monitor on a separate engine instance. The authors say this closes nearly every channel.
  • Enable batch-invariant kernels in vLLM.
  • Isolate or salt the prefix cache per user.
  • Test it: the same prompt on a full and an idle server must give bit-identical output.

My take: the setup is contrived today and needs helper agents, but the fixes are cheap. Apply them before you put an AI monitor on the same box as the thing it watches.
